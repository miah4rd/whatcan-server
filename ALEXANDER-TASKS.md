# Задачи для Александра (сторона amoCRM / Salesbot)

Это вещи, которые нельзя починить в коде api-server — они на стороне amoCRM
(конфиг Salesbot, данные контактов, интеграции каналов). Копилот со своей
стороны уже подстрахован; ниже — что именно и почему нужно сделать.

---

## 1. Дубль-отправка: одно сообщение уходит клиенту дважды (две беседы)

**Симптом.** Брокер нажимает «Approve & Send» один раз — клиент получает два
одинаковых сообщения подряд. В amoCRM видно две отдельные беседы (пример:
лид **22883683 Angus Wheaton**, беседы **A26132** и **A26133**, оба
«Delivered», текст идентичный).

**ДОКАЗАНО ФАКТАМИ (проверено 2026-07-29 по API + нашей БД):**
- `approve.ts` запустил отправку **ровно один раз**. В `sent_messages` для лида
  22883683 — **одна** строка (suggestion 1e11dffd…, «Salesbot 22127 triggered»,
  2026-07-29 13:01:02). Ретраев в `triggerSalesbot` нет + атомарный
  идемпотентный guard (`UPDATE ... WHERE status='pending'` + `sent_messages`)
  не даёт повторного аппрува того же саджеста. **Двойной отправки со стороны
  копилота НЕТ.**
- У лида **один** контакт (24893987), **один** телефон `+61459702132`, поле
  967477 «Last active chat messenger» = `58745` (линия Robert). Прошлой версии
  этой задачи (про «два номера в разных форматах») — **неверна**, номер один.

**ТОЧНАЯ ПРИЧИНА (со слов владельца, подтверждает данные).** Номер один и тот
же, но у WAhelp на него **две чат-сессии**: одна на формат **с `+`**
(`+61459702132`), другая **без `+`** (`61459702132`). Вся история переписки с
клиентом шла на версии **без плюса**. Наш один триггер Salesbot попадает в
**обе** сессии → клиент получает два одинаковых сообщения (беседы A26132 +
A26133). В карточке контакта телефон записан как `+61459702132` (с плюсом), а
живая беседа — на без-плюсовой; из-за расхождения формата WAhelp и держит два
треда.

**Значит:** размножение — **внутри WAhelp** (нормализация номера `+`/без `+`
рождает второй тред). Из кода api-server не чинится: наша адресация только на
уровне линии брокера (поле 967477 = source-id, не chat_id конкретной беседы),
формат номера мы не задаём.

**Как надо по-человечески:** бот НЕ должен «выбирать/резолвить» номер — он должен
просто продолжать **ту же самую беседу**, что уже шла (без-плюсовую), на тот же
номер. Сейчас же WAhelp плодит второй тред из-за формата.

**Что нужно сделать (твоя сторона / WAhelp):**
1. Посмотреть в WAhelp/amoCRM, почему у номера `+61459702132` на линии Robert
   **две** чат-сессии (беседы A26132 и A26133). Убрать/склеить лишнюю.
2. Проверить шаг «отправка клиенту» в сценарии Salesbot «Companion Robert»
   (бот 22127): он должен слать в **одну** беседу (последнюю активную), а не во
   все чат-сессии номера на линии.
3. Проверить, не системное ли это: поискать другие лиды, где один наш триггер
   даёт две доставки (тогда фиксить сам сценарий/интеграцию, а не один номер).

## 3. Обрыв сообщения при отправке: до клиента доходит только первая строка

**Симптом.** Бот отправляет длинное сообщение, а клиент получает только первую
строку (приветствие). Пример — лид **22486511** (Huzaifah): клиенту дошло только
«Hey Huzaifah 👋», остальное (4 абзаца) пришлось досылать вручную.

**Что проверено на стороне копилота (исключено):**
- В нашей БД `sent_messages` для этого лида текст записан **полностью** —
  603 символа («Hey Huzaifah 👋\n\nIt's been a little while…»).
- `updateLeadCustomField` пишет в поле 965907 полный текст как есть, без обрезки.
- В таймлайне amoCRM видно, что поле «companion massage» тоже получило **полный**
  текст.

**Значит:** обрыв происходит на шаге **отправки в Salesbot/WAhelp** — сообщение
режется по переносу строки (после «Hey Huzaifah 👋» идёт `\n\n`, и доходит только
до него). Похоже, сценарий «Companion Robert» (22127) / WAhelp либо режет на
первом переносе, либо разбивает по абзацам и досылает не все части (WhatsApp
режет быстрые последовательные сообщения).

**Что нужно:**
1. Проверить шаг «отправка сообщения» в сценарии Salesbot: как он обрабатывает
   многострочный текст из поля (переносы `\n` / `\n\n`). Должен слать **весь**
   текст одним сообщением, а не только первую строку/абзац.
2. Если WAhelp разбивает по абзацам и часть теряется — настроить, чтобы слал одним
   сообщением (WhatsApp поддерживает переносы строк внутри одного сообщения).

## 2. (Ранее) Рассинхрон меток времени: content (Moscow) vs lead_messages (UTC)

Напоминание по открытому вопросу: у нас две внутренние копии переписки —
`content` (таймстемпы в Moscow, UTC+3) и `lead_messages` (UTC). Они расходятся
на ~3 часа, из-за чего иногда лид неправильно всплывает/не всплывает в LIVE
(пример был с Ansar). Правильное решение — один авторитетный источник времени.
Пока живёт как известный компромисс; когда дойдут руки — обсудим единый источник.
