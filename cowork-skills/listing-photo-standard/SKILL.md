# ⛔ ИСТОЧНИКИ: AIRBNB И BOOKING — ОСНОВА, ОСТАЛЬНОЕ — ИСКЛЮЧЕНИЕ

**Указание владельца бизнеса 19.09.2026, прямым текстом: «Фото брать айрбнб и
букинг да, все верно, как основа, но если там нету то можно на других ресурсах
где есть, но в качестве исключения при условии что там действительно не
нашлось».**

Это смягчает закон от 17.09.2026, который запрещал всё, кроме двух OTA, и
оставлял объект в драфте навсегда. Прежняя редакция отменена, но приоритет
сохранён: **другие ресурсы открываются только после доказанного отсутствия на
Airbnb и Booking.**

## Лестница источников

| # | Источник | Когда можно |
|---|---|---|
| 1 | **Airbnb** | всегда, первый выбор |
| 2 | **Booking** | всегда, второй выбор |
| 3 | сайт самой виллы, Agoda, Traveloka, Trip.com, Vrbo, Expedia, Instagram виллы, **пин Google Maps**, каталоги долгосрока, набор от владельца | **только как исключение**, после доказанного отсутствия на Airbnb и Booking |

## Порядок применения исключения

1. Проверить Airbnb и Booking **не меньше чем пятью разными формулировками**
   запроса. Для Booking проверять и редирект: если страница объекта уводит на
   общую выдачу по району — листинга там нет.
2. Ноль попаданий на обоих → исключение открыто.
3. В `property_private.notes` обязательна строка вида:
   `PHOTOS BY EXCEPTION (owner rule 19 Sep 2026): not on Airbnb or Booking - checked with <N> query formulations: "<формулировка 1>", "<формулировка 2>"... Photos taken from <источник>.`
4. Атрибуция проверяется **так же строго**, как для OTA — раздел ниже. Исключение
   касается источника кадров, а не права поставить чужую виллу.
5. Всё остальное — отбор, обложка, покрытие, порог 8 кадров — **без послаблений**.

**Исключение не отменяет качество.** Если на других ресурсах только кадры
обочины, стройки или три одинаковых фото — это то же самое, что фото нет:
листинг остаётся драфтом. Прецедент 17.09.2026, `R-YUD-078` Villa Nemu: на пине
три одинаковых кадра обочины со стройкой.

## Если не нашлось нигде

**Листинг остаётся `is_draft = true`.**

1. В `property_private.notes`:
   `NO PHOTOS - not on Airbnb or Booking and nothing usable elsewhere. Checked: <формулировки>. Draft until our own shoot or the owner sends a set.`
2. Вопрос про фото уходит **боту** в TAKEN TO WORK, не задачей человеку
   (см. `listing-qualification-standard`).
3. В отчёте владельцу — отдельной строкой, что объект готов по данным, но стоит
   без фото.

## Набор от владельца не отменяет проверку OTA

Владелец прислал папку — сначала всё равно Airbnb и Booking. Его набор
подтверждает атрибуцию, качество обычно хуже.

Прецедент 13.09.2026, `R-YUD-104` Villa Luna Kedungu: опубликовали 27 кадров из
Drive-папки владелицы, владелец бизнеса забраковал — мутные, низкий контраст, ни
одного кадра, где здание и бассейн вместе. У виллы при этом был свой Airbnb на
71 кадр. Галерею пересобрали в тот же день, анонс в WhatsApp пришлось удалять.

## Почему приоритет именно такой

- 08.09.2026 `R-YUD-089` вышел с 9 кадрами с пина, при этом вилла лежала на
  Vrbo с 20. `R-YUD-090` вышел с каталожными кадрами, при этом был Airbnb на 34.
  Оба пересобраны.
- 13.09.2026 `R-YUD-105` Di Villa Bali — 8 кадров с пина, ни экстерьера, ни
  бассейна, единственный наружный кадр — ворота с байком.

Смысл лестницы: не запретить прочие источники, а не допустить, чтобы с пина
брали тогда, когда рядом лежит нормальный Airbnb.

# ⛔ ВОДЯНОЙ ЗНАК И ВЫВЕСКА С ИМЕНЕМ ВИЛЛЫ — КАДР НЕ ИДЁТ В ГАЛЕРЕЮ

Отдельно вынесено, потому что исключение из предыдущего раздела открывает
Instagram и пины, а там кадры часто заклеймены названием виллы.

**Имя виллы не уходит наружу ни текстом, ни картинкой.** В `title` и
`description` оно не пишется никогда, и точно так же не публикуется кадр, на
котором это имя читается: вывеска на воротах, логотип на стене, **полупрозрачный
вотермарк поверх фотографии**.

Причина та же, что и для `title`: конкурент читает имя, находит владельца,
уводит объект.

Прецедент 19.09.2026, Villa Evelyn (`R-YUD-118`): виллы нет ни на Airbnb, ни на
Booking, исключение открыто, на пине Google Maps нашлось 6 кадров — и на всех
шести по центру стоит вотермарк `VILLA EVELYN — PADONAN, CANGGU, BALI`. Кадры
использовать нельзя, несмотря на открытое исключение.

Что можно сделать: взять кадры, где вотермарк не перекрывает сюжет и поддаётся
обрезке, и обрезать; либо просить набор у владельца; либо ставить свою съёмку.
Замазывать чужой вотермарк — нельзя.

# КАК ДОСТАВАТЬ

**Поиск прямой ссылки.** Через Bing или DuckDuckGo из встроенного браузера
(см. `google-search-via-iframe`). Bing прячет URL за редиректом — разворачивать
параметр `u=a1<base64>` из href'ов `li.b_algo a`:

```js
const m = href.match(/[&?]u=a1([A-Za-z0-9_-]+)/);
let b = m[1].replace(/-/g,'+').replace(/_/g,'/'); while (b.length % 4) b += '=';
atob(b);   // → https://www.airbnb.com/rooms/<id>
```

**Airbnb.** Открыть страницу комнаты, подождать загрузку, выгрести из DOM:
```js
[...document.documentElement.innerHTML.matchAll(/https:\/\/a0\.muscache\.com\/im\/pictures\/[^"'\\ )]+?\.(?:jpe?g|png)/gi)]
```
К URL добавлять `?im_w=1440`. Первый кадр в списке часто логотип Airbnb — выбросить.
Пути бывают трёх видов, все рабочие: `miso/Hosting-<id>/original/<uuid>.jpeg`,
`hosting/Hosting-<base64>/original/<uuid>.jpeg` и короткие `<uuid>.jpg` в корне
`/im/pictures/`. **Не нормализовать пути** — брать ровно тот URL, что в DOM.
Фильтровать служебные `PlatformAssets` и `Favicons`.

**Booking.** URL кадра работает только вместе с подписью `?k=<hash>&o=`.
Без query — 403 и пустая картинка. Регулярка обязана захватывать query:
```js
/https:\/\/cf\.bstatic\.com\/xdata\/images\/hotel\/[a-z0-9x]+\/(\d+)\.(?:jpg|jpeg|png)(\?k=[a-f0-9]+(?:&amp;|&)o=[^"'\\ )]*)?/gi
```
Размерный сегмент можно поднять до `max1024x768`, подпись не трогать.
Дедуп — по числовому id файла.

**Пин Google Maps (только по исключению).** Places API (New), ключ в
`api-first-rule`, вызывать с нейтрального домена `example.com`:

```js
// 1) найти место и получить photos[].name
fetch('https://places.googleapis.com/v1/places:searchText',{method:'POST',
 headers:{'Content-Type':'application/json','X-Goog-Api-Key':k,
  'X-Goog-FieldMask':'places.displayName,places.internationalPhoneNumber,places.photos'},
 body:JSON.stringify({textQuery:'<имя виллы> <район> Bali'})});
// 2) по каждому photos[].name получить прямую ссылку
fetch('https://places.googleapis.com/v1/'+p.name+'/media?maxWidthPx=1600&skipHttpRedirect=true&key='+k)
// → { photoUri: "https://lh3.googleusercontent.com/..." }
```

`skipHttpRedirect=true` обязателен, иначе вернётся сама картинка, а не JSON со
ссылкой. Кадры с пина почти всегда вертикальные и часто с вотермарком — смотреть
глазами до импорта.

`a0.muscache.com`, `cf.bstatic.com` и `lh3.googleusercontent.com` импортёром
тянутся нормально.

# ⛔ АТРИБУЦИЯ: ЧЕМ ДОКАЗЫВАЕТСЯ, ЧТО ЭТО ТА ЖЕ ВИЛЛА

По убыванию силы:

1. **Телефон на пине Google Maps = телефон контакта в amoCRM.** Сильнейший признак.
2. **Имя хоста на Airbnb = имя владельца в переписке.** Прецеденты: Villa Luna
   Kedungu, хост **Galuh** — та самая Ibu Galuh из переписки. Casa Bumbak, хост
   **Ronald** — тот самый Ronald, с которым мы переписываемся.
3. **Совпадение архитектуры на кадрах** — фасад, материалы, планировка, число спален.
4. Имя виллы + район. Работает, но слабее всего: тёзок много.

Airbnb часто указывает **приблизительный район** («South Kuta» вместо Чангу) —
это не повод отвергать, но и не подтверждение. Похожее имя в другом районе —
другая вилла, фото не берём.

**Гейт не пройден — фото не берём, даже если набор красивый.** Прецедент
17.09.2026: под Villa Nemu в Мунггу нашёлся Airbnb «New 2-bedroom villa in
Munggu» — 2BR, тот же район, но хост Serenity Property Bali, а не Amanda,
телефон не совпал, и в описании общий спортзал «в здании», то есть комплекс.
Набор отвергли.

# ⛔ ГАЛЕРЕЯ — ЭТО ОТБОР, А НЕ СВАЛКА

Указание владельца 08.09.2026: **«тебе нужно научиться отличать красивые кадры
от некрасивых».** Найденный набор целиком на сайт не выкладывается.

## Что выбрасывается всегда

| Что | Почему |
|---|---|
| **Кадр с водяным знаком чужого агентства** (BALIHOMEIMMO, логотипы каталогов) | Реклама конкурента на нашей карточке |
| **Кадр с вывеской, логотипом или вотермарком имени виллы** | Имя виллы наружу не уходит — см. отдельный раздел выше |
| **Бассейн у глухой стены**, без здания в кадре | Не видно, что за дом |
| Обрезанный кадр: половина бассейна, кусок парапета, угол забора | Не читается сюжет |
| Половина площади — пустая белая стена или бамбуковый забор | Пусто |
| Съёмка **сверху вниз внутрь комнаты** через лестничный пролёт | Неразборчиво |
| Обрезанная кровать, кусок матраса, «полкадра мебели» | Брак кадрирования |
| Ступени, дверь, коридор, деталь без объекта | Нечего смотреть |
| Прачечная, гардероб, техника крупным планом, счётчик, мусорный бак | |
| Тёмный кадр (средняя яркость < 120) | |
| Вертикальный кадр (пропорция < 1.2) | Ломает сетку |
| Мутный, низкоконтрастный, засвеченный кадр | За это забраковали первую галерею R-YUD-104 |
| Пять почти одинаковых спален или кухонь подряд | Оставить 2-3 разных |
| Дубли одного кадра, приехавшие из разных источников | Сверять глазами после импорта |

## ⛔ ФОКУС — КОНКРЕТНАЯ ВИЛЛА, А НЕ КОМПЛЕКС

Аренду снимают **юнит**, а не проект.

- Кадры всего комплекса (ряд одинаковых юнитов, аэросъёмка) — **максимум два и
  только в самом конце галереи**.
- Обложкой кадр комплекса **не ставится никогда**.
- Первые кадры — всегда сам юнит: его фасад, его бассейн, его интерьер.
- В комплексе с разными типами вилл кадры чужого типа не берём вообще.

# ⛔ ОБЛОЖКА: НА КАДРЕ ДОЛЖНО БЫТЬ ВИДНО ЗДАНИЕ ВИЛЛЫ

**Проверка одним вопросом: «видно ли на этом кадре здание виллы?»**
Нет — обложкой не ставим. Здание = фасад, стеклянная стена, крыша, входная
группа, второй этаж, терраса с объёмом. Не считаются: глухая стена, бамбуковый
забор, подпорная стенка, парапет бассейна, ворота с припаркованным байком.

## Порядок выбора

1. **Бассейн на переднем плане + здание виллы за ним**, днём, широким планом.
   Так построено большинство живых обложек: `R-YUD-070`, `R-YUD-071`, `R-YUD-074`,
   `R-YUD-075`, `R-YUD-076`, `R-YUD-081`, `R-AME-028`, `R-AME-030`, `R-AME-033`,
   `R-YUD-054`, `R-YUD-061`, `R-DESTI-003`, `R-DESTI-016`, `R-YUD-089`, `R-YUD-090`,
   `R-YUD-100`…`R-YUD-104`, `R-YUD-114`, `R-YUD-115`.
2. **Выразительный фасад или входная группа.**
3. **Терраса или зона отдыха с зеленью и объёмом.**
4. Интерьер — только если экстерьера нет вообще, и сразу сказать владельцу, что
   обложка временная.

Обложкой не ставить: бассейн без здания, кадр комплекса, санузел, спальню,
пустой патио, деталь, рендер, тёмный кадр, коридор, парковку, кадр с вывеской.

**Объект, у которого экстерьера нет ни в одном источнике** — частый случай при
работе по исключению. Прецедент 19.09.2026, Villa Bersinar: 26 кадров на Booking
плюс 7 с пина, и ни одного фасада — только интерьеры и закрытый плунж-бассейн
изнутри. Такой объект публикуется только с прямого согласия владельца бизнеса,
с пометкой в `notes` и строкой в анонсе про временную обложку.

## Как выбирать: смотреть глазами на крупный контактный лист

Яркость и пропорции — фильтр мусора, **не выбор обложки**: «бассейн + фасад» и
«бассейн + глухая стена» дают одинаковую яркость и одинаковую долю синего.

Контактный лист — **grid с явным `grid-template-columns`**, плитки не меньше
245×165, партиями по 20-36. Flex с процентными ширинами даёт колонку-полоску.
Ширину вьюпорта поднять до 1000 через `resize_window`, иначе третья колонка
обрезается.

```js
document.documentElement.innerHTML='<body style="margin:0"><div id=g style="display:grid;grid-template-columns:245px 245px 245px 245px;gap:2px"></div></body>';
document.getElementById('g').innerHTML=f.map((s,i)=>
 `<div style="position:relative"><img src="${s}" style="width:245px;height:165px;object-fit:cover;display:block"><span style="position:absolute;top:1px;left:1px;background:#c00;color:#fff;font:bold 17px sans-serif;padding:0 6px">${i+1}</span></div>`).join('');
await new Promise(r=>setTimeout(r,9000));
```

Строить на вкладке с нормальным CSS (`unicorn-properties.com`, страница OTA,
`example.com` с явным grid). Дождаться загрузки, потом `computer{action:"screenshot"}`.
**Смотреть весь набор до публикации**, а не первые девять кадров.

## Проверка после смены обложки

```js
[...document.querySelectorAll('a[href*="property"]')]
 .filter(a=>/<ID>/.test(a.getAttribute('href')))
 .map(a=>a.getAttribute('href').split('/').pop()+' -> '+a.querySelector('img').src.split('/').pop())
```

**Карточка каталога — карусель**, кадр на скриншоте обычно НЕ обложка.
Надёжнее читать `meta[property="og:image"]` на самой странице объекта: сайт —
SPA, в сыром HTML стоит дефолтный баннер, а реальная обложка проставляется
в рантайме.

## ⛔ Обложка сменилась — анонс переотправляется с версионным параметром

WhatsApp кэширует превью по URL. Поменяли обложку, удалили сообщение, отправили
заново тот же URL — в превью остаётся старая картинка. Обход:
`https://unicorn-properties.com/property/<ID>?v=2`, номер увеличивать при каждой
следующей замене. Старое сообщение удалять через `/deleteMessage/`, новый
`idMessage` записывать в журнал. Подробности — `unicorn-whatsapp-greenapi`.

# НОРМА НАБОРА — 15-20 КАДРОВ

Покрытие: экстерьер или бассейн, гостиная или кухня, хотя бы одна спальня, санузел.

**Меньше 15 — публикуем всё равно**, и тогда:
- в `property_private.notes` — `PHOTO SET INCOMPLETE - N photos, target 15-20`;
- в amoCRM — следующий шаг: запросить комплект либо поставить съёмку;
- в анонс — `Photo set is incomplete for now, N frames. More to follow.`

**Порог публикации — 8 кадров И покрытие И пригодная обложка.** Не проходит —
`is_draft = true`, в `property_private.notes` строка
`PHOTOS BELOW PUBLISH THRESHOLD - N photos`, а вопрос про фото уходит **боту**
в TAKEN TO WORK.

Порог снимается **только прямым указанием владельца бизнеса по конкретному ID**,
и причина пишется в `notes`. Прецедент 17.09.2026: `R-YUD-105` Di Villa Bali
опубликован на 8 кадрах по его прямому указанию «публикуй 8 пка».

**Больше 20 — режем.** Лишние однотипные кадры разбавляют карточку.
Совсем без фото не публикуем.

## АВТОПРОВЕРКА: ЯРКОСТЬ И ПРОПОРЦИИ

```js
const rs = await Promise.all(f.map((u,i)=>new Promise(r=>{
  const im=new Image(); im.crossOrigin="anonymous";
  im.onload=()=>{
    const c=document.createElement('canvas'); c.width=48; c.height=32;
    const x=c.getContext('2d'); x.drawImage(im,0,0,48,32);
    const d=x.getImageData(0,0,48,32).data; let s=0;
    for(let k=0;k<d.length;k+=4) s+=0.299*d[k]+0.587*d[k+1]+0.114*d[k+2];
    r((i+1)+":"+Math.round(s/(d.length/4))+":"+(im.naturalWidth/im.naturalHeight).toFixed(2));
  };
  im.onerror=()=>r((i+1)+":ERR"); im.src=B+u;})));
```

Яркость < 120 → выбросить. Пропорция < 1.2 → не брать. Одинаковая яркость у
нескольких подряд — дубли или подмена.

## НАЗВАНИЕ ВИЛЛЫ НЕ ПИСАТЬ

В `title` и `description` **никогда**. Формула:
`<кол-во спален>BR Villa with <1-2 фишки> in <район>`.
Название живёт только в `property_private.notes` и в amoCRM.
Кадры с вывеской, логотипом или вотермарком имени виллы в галерею не ставить.

## КОПИЯ ГАЛЕРЕИ В DRIVE-ПАПКЕ

Опубликованный набор дублируется в свою Drive-папку листинга тем же составом и в
том же порядке, файлы нумеруются `01`, `02`, …
Фото взяты с OTA и скачать их в папку нельзя — кладём **манифест**: док со
списком опубликованных Supabase-URL по порядку, источником и пометкой, какой
кадр обложка.
**Почистили галерею или сменили обложку — папка и манифест обновляются в тот же
заход**, старый манифест не стирается, рядом кладётся `v2`.
Имя папки, родители, доступ — в `listing-internal-data-gate`.

## ТЕХНИКА

- Импорт: `SELECT import_property_images('<ID>', ARRAY[...]::text[], 'append');`
  5–10 ссылок за вызов, предел 20. **Кадры 3000px и выше — по 2.** HEIC — по 3.
- `WORKER_RESOURCE_LIMIT` (546), таймаут, `499` — **не ошибки**, повторять тот же
  вызов меньшими пачками, пока счётчик растёт. Часть кадров при этом обычно уже
  залилась — проверять `totalImages`, а не `imported`.
- **Всегда читать `failed`.** Импортировано меньше, чем отправлено — часть URL
  отвалилась, это пишется в `notes`.
- Строку листинга сначала закоммитить, потом импортировать.
- `replace` на опубликованном листинге не использовать.
- Драфт сайт не отдаёт вообще — `is_draft = true` даёт «Property not found».
- Пересобрали галерею из нового источника — **старые кадры не удалять из
  storage**, просто не включать в новый массив `images`.

### ГЛАВНАЯ ЛОВУШКА: НЕ ПЕРЕСОБИРАТЬ МАССИВ ПО ИНДЕКСАМ

`SET images = ARRAY[images[1],images[32], ...]` **не идемпотентен**. Таймаут часто
означает, что запрос выполнился; повтор применяет перестановку второй раз,
индексы вылетают за границы, Postgres подставляет `NULL`, вся галерея становится
одной обложкой. Так сломался `R-YUD-070`.

**Пересборка — всегда явными URL целиком:**

```sql
UPDATE properties SET images = ARRAY['<url1>','<url2>', ...]::text[],
  updated_at = now() WHERE id = '<ID>';
```

Выбросить один кадр:
```sql
UPDATE properties SET images = array_remove(images,'<URL>'), updated_at=now() WHERE id='<ID>';
```

Поставить кадр обложкой, не трогая остальное:
```sql
UPDATE properties SET images = ARRAY['<URL>'] || array_remove(images,'<URL>'),
  updated_at = now() WHERE id = '<ID>';
```

Проверка после любой правки:
`array_length(images,1)` = `cardinality(array_remove(images,NULL))`.
