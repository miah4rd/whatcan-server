# Финал прогона: анонсы в группу и аудит

# ⛔ В ГРУППУ ИДУТ ТОЛЬКО АНОНСЫ ЛИСТИНГОВ

Указание владельца бизнеса 08.09.2026. **Отменяет прежнее требование слать в
Unicorn Rental сводный репорт прогона.**

## Что отменено

Репорт вида «проверено 13 карточек, отсеяно 8, вернули 1, дропнуто по полу 0» в
группу **не отправляется**. Брокеру он не нужен: он не работает воронку, он
работает объекты. Отправленный 08.09.2026 такой репорт пришлось удалять.

Вся эта информация идёт:
- **владельцу бизнеса** — в отчёт по прогону,
- **в amoCRM** — журнал в сделку `23211429`.

## Что остаётся

Только анонсы. **Один листинг = одно сообщение, три строки.** Формат, правило
одной ссылки на сообщение и причина (WhatsApp рисует превью только первой
ссылке) — в `unicorn-whatsapp-greenapi`, раздел «Анонс листинга».

Единственное дополнение к анонсам — **короткое предупреждение по конкретному
живому листингу**, если по нему нельзя котировать: цена на сайте наша оценка, а
владелец назвал другую; не подтверждено, юнит это или комплекс. Отдельным
коротким сообщением про этот объект, без сводки прогона.

## Чего в группу не пишем никогда

Группа — сто человек, включая людей вне компании:

- телефоны и имена владельцев, адреса, ссылки на пины и Drive-папки;
- внутренние причины, претензии к контактам, статистику воронки;
- суммы нашей комиссии и маржи;
- ID сделок amoCRM.

const T='8a3d673d65744bcd847708c8c871896f69e3a09c82784900a5';
await fetch(B+'/sendMessage/'+T,{method:'POST',
  headers:{'Content-Type':'application/json'},

Из вкладки встроенного браузера на нейтральном домене. Пауза 2-3 секунды между
сообщениями. Прогон закрыт только когда по каждому анонсу получен `idMessage` —
записывать их в журнал, без них не откатить неверную отправку.

# Аудит анонсов: что вышло на сайт, но не дошло до команды

Проблема, замеченная владельцем 05.09.2026: листинг публикуют — Юди, Амелия,
любой агент — и забывают написать в группу. Объект живёт на сайте, но брокеры
про него не знают и клиентам не предлагают.

**Выполняется в конце каждого прогона по листингам**, после того как свои
листинги опубликованы и анонсированы. Он про чужие.

## Механика — читаем историю группы через Green API

Проверено рабочим 05.09.2026.

```js
const r=await fetch(B+'/getChatHistory/'+T,{method:'POST',
  headers:{'Content-Type':'application/json'},
  body:JSON.stringify({chatId:'120363411017702009@g.us',count:100})});
const j=await r.json();
const ids=new Set();
j.forEach(m=>{const t=(m.textMessage||(m.extendedTextMessage&&m.extendedTextMessage.text)||m.caption||'');
  (t.match(/[A-Z]{1,2}-?[A-Z]{2,6}-\d+/g)||[]).forEach(x=>ids.add(x));});
```

`count:300` отдаёт около 139 сообщений глубиной до 10 августа, `count:40` — до
24 августа. Для суточной сверки хватает `count:100`.

**Чтение истории квоту тарифа Developer не тратит** — лимит в 3 чата в месяц про
отправку. Читаем только Unicorn Rental, другие группы не трогаем.

## Сверка с базой

```sql
SELECT id, title, area, bedrooms, monthly_price_idr, created_at::date
FROM properties
WHERE listing_type='rent' AND coalesce(is_draft,false)=false
  AND created_at > now() - interval '2 days'
ORDER BY created_at DESC;
```

Вычесть ID, найденные в чате. Остаток — необъявленные.

## Ограничения

- Сверка идёт **по ID листинга в тексте**. Агент написал «новая вилла в Сесехе»
  без ссылки — объект попадёт в список ложно. Поэтому владельцу это подаётся как
  «похоже, не анонсировали», а не как факт.
- Агенты могут писать в ONLY LISTINGS и Listing discussion — их не читаем.
- `created_at` меняется только при создании строки. Листинг, созданный давно и
  выведенный из драфта сегодня, по `created_at` не попадётся — смотреть и
  `updated_at`.

## Что делать с находками

- **Свежие, до 2 суток** — анонсировать по общему правилу: отдельное короткое
  сообщение на объект. Строку про temporary photos не писать, если неизвестно,
  чьи там фото.
- **Старше 2 суток** — не анонсировать молча, показать владельцу списком: за
  неделю набирается десяток, вываливать всё разом в группу из ста человек нельзя.

## Попутная проверка ценового пола

```sql
SELECT id, title, monthly_price_idr FROM properties
WHERE listing_type='rent' AND coalesce(is_draft,false)=false
  AND monthly_price_idr < 30000000;
```

Найденное **не снимать молча** — вынести на решение владельца бизнеса.
На 05.09.2026 так нашёлся `R-YUD-074` за 22,5 млн.

1. Каждый опубликованный листинг анонсирован **отдельным коротким сообщением**,
   одна ссылка на сообщение.
2. Аудит чужих анонсов прогнан, свежие находки анонсированы так же.
3. Ценовой пол 30 млн прогнан по опубликованным.
4. **Сводный репорт в группу НЕ отправлен** — он идёт владельцу и в журнал.
5. Журнал прогона записан в сделку `23211429` со всеми `idMessage`.
