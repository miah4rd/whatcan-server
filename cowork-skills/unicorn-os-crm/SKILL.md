# ⛔⛔⛔ ЗАПАСНОЙ ПУТЬ БЕЗ КОННЕКТОРА — ПРЯМОЙ HTTP С КЛЮЧОМ (владелец, 20.10.2026)

Прецеденты 19.10 и 20.10.2026: коннектор Unicorn OS был подключён к аккаунту (`ListConnectors`: connected), но выключен для чата запланированной задачи (`enabledInChat:false`). Инструментов `mcp__Unicorn_OS__*` не было, анонсы и журнал не ушли, владельцу ушёл пуш. Владелец включил коннектор для задачи и сказал: **«Владельцу про коннектор больше не писать»**.

## Правило (переопределяет всё ниже про пуш «коннектора нет» и «Инструментов нет»)
1. Старт: `RefreshMcpTools` → ToolSearch `+Unicorn_OS`. Есть инструменты — работать через них.
2. **Инструментов нет — не ждать и не писать владельцу.** Делать то же самое прямыми HTTP-запросами на сервер коннектора с его ключом (Bearer) из облачного Bash (`curl`):
   - сервер: `<OS_URL>` (база из ссылки коннектора в файле `OS-коннектор-для-коворкера.txt`, без хвоста с ключом);
   - заголовок: `Authorization: Bearer <OS_KEY>` (ключ из той же ссылки);
   - **анонс:** `POST <OS_URL>/team-announcement`, тело `{"text": "…текст анонса, ссылка последней строкой…"}`. Успех = `ok:true` + `id`;
   - **журнал:** `POST <OS_URL>/api/v4/leads/900002826/notes`, тело `[{"note_type":"common","params":{"text":"…"}}]`. Успех = 200 и `id` заметки;
   - **чтение/заметки в карточки:** тем же способом в формате amoCRM v4 (`GET /api/v4/leads/<id>`, `GET /api/v4/leads/<id>/notes`, `POST /api/v4/leads/<id>/notes`).
   - Пример: `curl -sS -X POST "<OS_URL>/team-announcement" -H "Authorization: Bearer <OS_KEY>" -H "Content-Type: application/json" -d '{"text":"New listing - ...\nPre - ...\nhttps://unicorn-properties.com/property/R-YUD-XXX"}'`
3. Не отвечает и прямой HTTP (сеть, 401) — всё, что не ушло, записать в отчёт и в документ проекта «Журнал прогонов листинга — <дата>» как долг следующего прогона. **Пуш владельцу про коннектор не слать.** Пуш — только если по делу есть что сообщить (опубликовано, нужно решение), и без слов про коннектор.
4. Перед отправкой хвоста — сверить журнал 900002826 (`GET /api/v4/leads/900002826/notes?limit=5&page=N`; список идёт по возрастанию id, `order` сервер игнорирует — брать последние страницы): нет ли уже id анонса для этого листинга.
5. Ключ — секрет: в заметки CRM, анонсы, документы проекта и отчёты его не выводить.

> **⚠ Плейсхолдеры `<OS_URL>` и `<OS_KEY>` владелец должен заменить значениями из файла `OS-коннектор-для-коворкера.txt`** (в запросе 20.10 ссылка не была вставлена). Любой, у кого есть этот скилл, получает доступ к CRM в пределах ключа.

# ⛔ КОННЕКТОР ПОДКЛЮЧАЕТСЯ ПОЗЖЕ — ДОГРУЗКА В ТОЙ ЖЕ СЕССИИ (19.10.2026)

Прецедент 18–19.10.2026: два сорсинговых прогона подряд искали `+Unicorn_OS` в начале и в конце (4 поиска, пауза 60 с), инструментов не было. 2. Перед финальным отчётом прогона — ещё один ToolSearch `+Unicorn_OS`. Появился → сделать догрузку сразу, в отчёте писать «сделано», а не «следующий прогон».

## Как делать догрузку (проверено 19.10.2026)
- **Найти ID карточек дня.** `find_leads` и фильтры `filter[...]`/`order[...]` в `GET /api/v4/leads` сервер игнорирует: список идёт по возрастанию id. Брать `crm_request GET /api/v4/leads?limit=100&page=N` с последних страниц (на 19.10 — стр. 9–11), ответ сохраняется в файл; разобрать в Bash: `data._embedded.leads`, отбор по `pipeline_id=11180334` и `created_at` (unix-секунды, 17.10.2026 00:00 UTC = 1792195200). Теги — в `_embedded.tags`.
- **Тег.** `crm_request PATCH /api/v4/leads`, тело `[{"id":<id>,"_embedded":{"tags":[{"name":"SRC:AI"}]}}, ...]`, до 50 за вызов. Теги заменяют весь список — если у карточки уже есть другие теги, переотправить их вместе с SRC:AI. Проверить выборочно `GET /api/v4/leads/<id>`.
- **Журнал.** `add_note` в 900002826, отдельной заметкой на каждый пропущенный день, с пометкой «posted <дата> - connector was unavailable on <дата>». Перед этим прочитать журнал: нет ли уже записи за этот день.
- После догрузки поправить копию в документе проекта «Журнал сорсинга листингов» / «Журнал прогонов листинга — <дата>».

# CRM = Unicorn OS. amoCRM больше нет

Указание владельца бизнеса 30.09.2026: **«Листинги переехали в операционную систему. Забудь про amoCRM. Мониторим только Unicorn OS.»**

## Главное правило

- **amoCRM не использовать вообще.** Не открывать `unicornproperty.amocrm.ru`, не делать туда запросов, не проверять «на всякий случай», не сверять с ней, не писать туда заметки и журналы, не учитывать её события в отчётах.
- Всё, что в других скилах сказано про amoCRM, читать как **Unicorn OS**. ID воронок, стадий и полей те же (Rental Listings `11180334`, QUALIFIED `87763162`, Details `87763166`, Inspection `87763170`, TAKEN TO WORK `87795530`, Closed-lost `143`, long term `88322310`, co-broke `88322314`; поля `968489` спальни, `968491` район, `968831` цена, `968833` owner verified, `968835` доступность, `968837` фото, `968829` Google Maps).
- Номера сделок amoCRM в старых заметках (например журнал `23211429`) — история, не рабочие адреса.

## Как работать

**Основной путь — коннектор Unicorn OS (MCP):**

| Задача | Инструмент |
|---|---|
| регламент (читать первым) | `regulation` (funnel `rental-listings`) |
| стадии воронки | `pipeline_stages` |
| список карточек по стадии / тексту / дате | `find_leads` (status_id, query, updated_from) |
| карточка целиком: поля, контакты, заметки, переписка WhatsApp | `lead_overview` (type 89 — сторона виллы, 90 — мы) |
| кто и когда двигал карточки | `stage_changes` (since, lead_id) |
| перевести по стадиям | `move_stage` |
| заметка | `add_note` |
| поменять поля | `update_lead` |
| создать карточку | `create_lead` (дубли по телефону отвечает duplicate:true) |
| анонс в Unicorn Rental | `send_team_announcement` |
| любой другой запрос формата amoCRM v4 | `crm_request` |

Доступ ключа — только воронка Rental Listings (+ HR `91000001`, HR New `91000011`). Клиентские воронки Rental и UNICORN закрыты.

## Доступ к OS (обновлено 20.10.2026)

- Коннектор подключён к аккаунту владельца как custom connector (Settings → Connectors → Add custom connector, ссылка из файла `OS-коннектор-для-коворкера.txt`). В сессии — **Unicorn_OS**, инструменты `mcp__Unicorn_OS__*`: `regulation`, `pipeline_stages`, `find_leads`, `lead_overview`, `stage_changes`, `move_stage`, `add_note`, `update_lead`, `create_lead`, `crm_request`, `send_team_announcement`, `send_whatsapp`, `create_marketplace_lead`.
- Для запланированной задачи коннектор должен быть **включён в настройках коннекторов самой задачи** (`enabledInChat:true`). Если `ListConnectors` показывает `connected:true, enabledInChat:false` — инструментов не будет: сразу прямой HTTP (раздел вверху), владельцу не писать.
- Перед выводом «инструментов нет» — `RefreshMcpTools` и ToolSearch `+Unicorn_OS` (прецеденты 13.10 и 19.10: коннектор появлялся позже в той же сессии).

**Порядок анонсов и журнала:**
- Анонсы в Unicorn Rental — только `send_team_announcement` / `crm_request POST /team-announcement` / прямой HTTP `POST /team-announcement`. `send_whatsapp` на группу и Green API для анонсов не использовать. Успех = `ok:true` с `id`.
- Журнал `900002826` — `add_note` / `crm_request POST /api/v4/leads/900002826/notes` / прямой HTTP. Разовый отказ классификатора на `add_note` — повторить один раз.
- Никогда не считать отправленным то, что не вернулось как отправленное (`ok:true` + `id`).

**Запасной путь для чтения — встроенный браузер, вкладка `https://os.unicorn-properties.com/os/` (вход уже есть):** same-origin `fetch('/os/api/...')` — `/os/api/leads?pipeline=rental-listings&active=all`, `/os/api/leads/<id>` (поля, `facts`, `messages`, `stageEvents` с `changed_at`/`to_stage`, `notes`), POST `/os/api/leads/<id>/notes` `{"text"}`. Ограничения: журнальная карточка `900002826` там не видна (404 «No such card») — журнал через коннектор или прямой HTTP; анонсов, regulation и stage_changes там нет. Медиа из переписки (фото владельца) через этот API не скачиваются.

**`/os-crm` из браузера не работает:** принимает только Bearer-ключ, вход в OS (cookie) его не авторизует → 401. Менять защиту CRM — только по прямому «да» владельца.

Ни коннектора, ни прямого HTTP, ни браузера — работу, которую можно, сделать, остальное записать долгом в документ проекта; на amoCRM не откатываться.

**Журнал прогонов — заметкой в карточку `900002826`.** Копия — документ проекта «Журнал прогонов листинга — <дата>».

## Ловушки OS (замечено 30.09.2026)

- **История стадий начинается с переезда (29.09.2026).** Более ранних событий `lead_status_changed` в OS нет.
- **Массовое `updated_at` в момент переноса.** Все перенесённые карточки получили `updated_at` около 29.09 12:19 UTC — фильтр «обновлены за сутки» ловит весь перенос, а не свежую работу.
- **`lead_added` в OS ≠ новая карточка от сорсинга.** Карточки, заведённые в amoCRM и перенесённые в OS, тоже дают `lead_added`. Свежую работу смотреть по переписке с источником `os.whatsapp` (yudi-main / yudi-2 / nikita-os) и по `stage_changes` после переноса.
- **Журнал событий OS не пишет сообщения** (`incoming_chat_message` → 204). Объём переписки считается только через `lead_overview` по карточкам.
- **Закрытия без причины.** Автопилот закрывает карточки в 143 без заметки (причина только в переписке), а часть карточек стоит в 143 вообще без события смены стадии (прецедент: Juli Villas #23238517). Любую карточку в 143 без заметки с причиной — читать переписку и сверять с регламентом.
- **Теги при переносе потерялись** (например SRC:AI). Аналитику по тегам не строить, пока теги не восстановлены.
- Большие выборки `find_leads` (вся стадия QUALIFIED) не помещаются в ответ — брать узкими фильтрами (`updated_from`, `query`).
- **Заметки журнала идут по возрастанию id**, `order[id]=desc` игнорируется — последние записи на последних страницах (`limit=5&page=N`, пустая страница = 204).
