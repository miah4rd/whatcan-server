## Как работать

**Основной путь — коннектор Unicorn OS (MCP):**

| Задача | Инструмент |
|---|---|
| стадии воронки | `pipeline_stages` |
| список карточек по стадии / тексту / дате | `find_leads` (status_id, query, updated_from) |
| карточка целиком: поля, контакты, заметки, переписка WhatsApp | `lead_overview` (type 89 — сторона виллы, 90 — мы) |
| кто и когда двигал карточки | `stage_changes` (since, lead_id) |
| перевести по стадиям | `move_stage` |
| заметка | `add_note` |
| поменять поля | `update_lead` |
| создать карточку | `create_lead` (дубли по телефону отвечает duplicate:true) |
| любой другой запрос формата amoCRM v4 | `crm_request` |

Доступ ключа — только воронка Rental Listings. Карточки клиентов закрыты.

Запасной путь, если коннектора нет в сессии: API формата amoCRM v4 по адресу `https://os.unicorn-properties.com/os-crm` с вкладки на `https://os.unicorn-properties.com`. Ключ в скил и документы не пишется. Коннектора нет и запасной путь заблокирован — стоп и сказать владельцу, не откатываться на amoCRM.

## Ловушки OS (замечено 30.09.2026)

- **История стадий начинается с переезда (29.09.2026).** Более ранних событий `lead_status_changed` в OS нет.
- **Массовое `updated_at` в момент переноса.** Все перенесённые карточки получили `updated_at` около 29.09 12:19 UTC — фильтр «обновлены за сутки» ловит весь перенос, а не свежую работу.
- **`lead_added` в OS ≠ новая карточка от сорсинга.** Карточки, заведённые в amoCRM и перенесённые в OS, тоже дают `lead_added`. Свежую работу OS смотреть по переписке с источником `os.whatsapp` (номера yudi-main / yudi-2 / nikita-os) и по `stage_changes` после переноса.
- **Журнал событий OS не пишет сообщения** (`incoming_chat_message` → 204). Объём переписки считается только через `lead_overview` по карточкам.
- **Закрытия без причины.** Автопилот закрывает карточки в 143 без заметки (причина только в переписке), а часть карточек стоит в 143 вообще без события смены стадии (прецедент: Juli Villas #23238517 — хороший объект, закрыт без следа). Любую карточку в 143 без заметки с причиной — читать переписку и сверять с регламентом, а не считать закрытой по делу.
- **Теги при переносе потерялись** (например SRC:AI). Аналитику по тегам не строить, пока теги не восстановлены.
- Большие выборки `find_leads` (вся стадия QUALIFIED) не помещаются в ответ — брать узкими фильтрами (`updated_from` после переноса, `query`), а не целиком.
