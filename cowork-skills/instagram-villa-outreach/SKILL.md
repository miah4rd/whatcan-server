# Instagram как слой добычи по виллам — Unicorn Property

Дополняет `fb-lead-contact-rule` (слой 1В), `bali-catalog-sourcing-rule`
и `listing-card-standard`.

**Зачем этот слой существует:** когда в остро дефицитном районе контакты на
Google Maps выгреблены, мы не меняем район — мы меняем метод. Instagram и есть
следующий метод по тому же району.

# ⛔⛔ ГЛАВНОЕ ПРАВИЛО: 10 ДИРЕКТОВ КАЖДЫЙ ДЕНЬ ПО ВЫГРЕБЛЕННОМУ РАЙОНУ

**Указание владельца 21.09.2026, дословно:** «нужно 10 инст каждый день
по району, который выгребли, сейчас это Сесех».

Это правило **переопределяет** прежнюю запись «9 директов на каждый из двух
аккаунтов, 18 в день суммарно» (19.09.2026).

## Что это значит буквально

- **Норма 10 исходящих директов в день**, суммарно по всем рабочим аккаунтам.
- **Район выбирается не по кубу, а по факту выгребленности карт.** Признак:
  дедуп по телефону в этом районе даёт близко к 100% дублей два дня подряд.
- **Сейчас это Сесех** (пояс Сесех / Мунггу / Чемаги — один пляжный пояс,
  считать районы раздельно, но обходить вместе, фактический пин писать во FLAGS).
- Директы **в дневной таргет 20 карточек не входят и его не замещают**
  (см. `listing-card-standard`). Это задел на завтра.
- Район меняется, когда карты выгребают следующий.

История планки: 15 → 10 (08.09) → 20 (14.09) → 15 (14.09) → 10 (19.09) →
9+9=18 по аккаунтам (20.09) → **10 в день по выгребленному району
(21.09, действует)**.

# ШАГ 1 КАЖДОГО ДНЯ. ИНБОКС ПРОВЕРЯЕТСЯ ПЕРВЫМ, ДО ЛЮБОЙ ОТПРАВКИ

**Указание владельца 19.09.2026.** Директ уходит сегодня, ответ приходит
в течение дня, а читаем мы его на следующем прогоне. Значит проверка инбокса —
не «когда-нибудь в конце», а **первое действие дня**.

## Порядок

1. Проверить инбокс каждого рабочего аккаунта.
2. По каждому новому ответу выполнить проверку на автоответ.
3. **Ответ с номером → карточка в amoCRM в тот же день**, до новых исходящих.
4. Ответ без номера, но человеческий → ответить и вести переписку.
5. Только после этого тратить дневную норму.

Отправленный директ — это незакрытый долг. Пока ответ лежит непрочитанным, мы
платим лимитом за новые касания и не забираем то, что уже пришло.

## Карточка из ответа

Воронка Listing Rental 11180334, статус 87738346, тег SRC:AI. Если ответивший
держит несколько вилл — стадия co-broke 88322314.

```
CONTACT SOURCE: Instagram DM reply (@аккаунт)
CHECKS: duplicate search in amoCRM by phone AND by villa name - <результат>
```

В `TO ASK ON FIRST TOUCH` обязателен вопрос «владелец или управляющий».

⛔ **Номер из шапки профиля контактом НЕ считается.** Разрешённые источники —
пин Google Maps, собственный домен виллы, ответ в директе. Шапка Instagram
в этот список не входит: там часто сидит менеджер или оператор.

# ⛔⛔ КАК ОТПРАВЛЯТЬ — ЕДИНСТВЕННЫЙ РАБОЧИЙ МАРШРУТ (проверено 21.09.2026)

```
профиль виллы
 -> кнопка Message на профиле
 -> открывается ПУЗЫРЬ ЧАТА поверх страницы (URL не меняется)
 -> клик по полю ввода (или .focus() на div[contenteditable="true"])
 -> напечатать текст
 -> ⛔ КЛИКНУТЬ КНОПКУ Send. ENTER НЕ ОТПРАВЛЯЕТ.
```

## Четыре факта, каждый из которых ломал прогон

1. **Enter в пузыре чата не отправляет.** Текст остаётся в поле, тред не
   создаётся, в инбоксе ничего не появляется. Ловится тем, что аккаунт не
   всплыл наверх инбокса. Отправляет только клик по кнопке с текстом `Send`.
2. **Ширина вьюпорта должна быть не меньше 1280.** При 416px профиль
   показывает только `Follow`, кнопка `Message` в DOM отсутствует.
   `resize_window` с width 1280, потом перезагрузить страницу.
3. **Композер `/direct/new/` мёртв и на личном аккаунте тоже.** Диалог
   «New message» открывается, текст в поиск получателя вводится, но список
   пуст: `/api/v1/direct_v2/ranked_recipients/` отдаёт **HTTP 200 с пустым
   телом**. Прежняя запись, что это беда только профессионального аккаунта,
   неверна. Новые переписки через композер начать нельзя.
4. **У профилей без бизнес-статуса кнопки Message нет вообще.** Такие
   аккаунты недостижимы ни одним маршрутом и уходят в пул с причиной
   «no DM route». Проверка бизнес-статуса до попытки экономит целый заход:
   `/"is_business_account":true/.test(html)`.

## Код клика

```js
// открыть чат
const b=[...document.querySelectorAll('div[role="button"],button')]
  .find(x=>(x.innerText||'').trim()==='Message');
b.click(); await new Promise(r=>setTimeout(r,5000));
document.querySelector('div[contenteditable="true"]').focus();
// ...напечатать текст инструментом ввода, не через JS...
// отправить
const s=[...document.querySelectorAll('div[role="button"],button')]
  .find(x=>((x.innerText||x.getAttribute('aria-label')||'').trim())==='Send');
s.click();
```

⛔ Печатать текст **только инструментом ввода**, не присваиванием в DOM —
React не увидит значение и кнопка Send останется неактивной.

⛔ **Клик по координатам недоступен**, когда панель браузера скрыта: скриншот
не снимается, а `left_click` по координате требует свежего скриншота.
Работать через `ref` из `find` или через JS-клик.

## Проверка, что сообщение реально ушло

После каждой отправки — аккаунт обязан быть **наверху инбокса**:

```js
const Q=String.fromCharCode(63);
const r=await fetch('/api/v1/direct_v2/inbox/'+Q+'limit=5&thread_message_limit=2',
  {headers:{'x-ig-app-id':'936619743392459'}});
```

Не всплыл — сообщение не ушло, это стоп-сигнал, а не повод повторить.

⛔ Отправка через `/api/v1/direct_v2/threads/broadcast/text/` не работает
и опасна: HTTP 200 с HTML вместо JSON, ничего не отправляется, сессия падает
на экран выбора профиля. Только UI.

## Ответ на сторис или хайлайт — запасной маршрут

Открыть `/stories/highlights/<id>/`, подтвердить «View Story», написать
в поле «Reply to <user>…», Send. Нужен, когда кнопки Message нет, но есть
активные хайлайты.

## Антибан — что важнее самого числа

- **Общие лимиты Instagram в 50-150 сообщений в день к нам не относятся.**
  Это переписка с теми, кто уже написал или подписан. Холодный первый директ
  незнакомому — отдельная, гораздо более узкая категория.
- Внешний замер: новый аккаунт держит 5-10 холодных в день, разогретый 15-20,
  устоявшийся потолок 20-35. Десять лежит внутри безопасной зоны.
- **Одинаковый текст больше десяти раз подряд даёт DM-блок почти мгновенно.**
  Формулировка каждый раз своя, и на связке аккаунтов тоже.
- Жалобы получателей роняют лимит сразу.
- Директы растягивать по дню, не пачкой подряд.
- **Один и тот же аккаунт виллы не писать с двух наших аккаунтов.**

## Стоп-сигналы — прекращать в тот же момент, по каждому аккаунту отдельно

- «Try again later», «Action Blocked», «We restrict certain activity…»;
- три и более неотправленных сообщения за день;
- отправка визуально прошла, но аккаунт не всплыл наверх инбокса.

Блок на одном аккаунте = пауза 48-72 часа **на этом аккаунте**.

## Объём не лечит нулевую конверсию

На 21.09.2026 отправлено суммарно около 29 директов, реальных ответов
владельца **ноль**, автоответов два. Удвоение объёма было решением владельца,
но **мерить отдачу обязательно**: если на сотне отправленных ответов ноль,
проблема в тексте или в канале, и её не лечит третий аккаунт.

# ГЛАВНАЯ ЛОВУШКА: АВТООТВЕТ INSTAGRAM BUSINESS, НЕ ВЛАДЕЛЕЦ

Из девяти директов 17.09 пришло два ответа, и оба — автоответ Instagram Business.

Признаки:
- в сыром JSON стоит `"processed_business_suggestion": true`;
- текст дословно одинаковый на разных аккаунтах;
- номер WhatsApp один и тот же на двух виллах: `+6282233080265`;
- язык «our team», «they will be happy».

Карточку объекта по такому номеру не заводить. Если номер отвечает и держит
несколько вилл — co-broke карточка (пример: лид 23608543).

## Обязательная проверка ответа

1. Читать сырой айтем `/api/v1/direct_v2/threads/<id>` — у автоответов текст
   лежит в `.link.text`.
2. Флаг `processed_business_suggestion === true` означает автоответ.
3. Сверить номер с номерами других вилл в прогоне и в CRM.
4. Только если флага нет, текст человеческий и номер уникален — карточка.

```js
const Q=String.fromCharCode(63);
const r = await fetch('/api/v1/direct_v2/inbox/'+Q+'limit=40',
  {headers:{'x-ig-app-id':'936619743392459'}});
const j = await r.json();            // j.inbox.threads
```

⛔ `/api/v1/direct_v2/threads/<id>/` c параметрами иногда отдаёт **HTTP 500**.
Не считать это блокировкой: читать тред через инбокс с `thread_message_limit`.

`ds_user_id` из cookie — это мы, из отправителей исключать.

# ГЛАВНЫЙ ИНСТРУМЕНТ: `meta[name="description"]` ПРОФИЛЯ

```js
window.meta=async function(u){
 const r=await fetch('/'+u+'/',{headers:{'Accept':'text/html'}});
 const d=new DOMParser().parseFromString(await r.text(),'text/html');
 const m=d.querySelector('meta[name="description"]');
 return (m?m.content:'').replace(/\s+/g,' ');
};
```

Пауза 1.8-2.5 секунды. Около 30 вызовов подряд без троттлинга.
Оттуда же дёшево берутся `profile_id` и `is_business_account`.

Не читать шапку из `document.body.innerText` — страница режет её на «… more».
`/api/v1/users/web_profile_info` не использовать — стабильный 429.
Функции `window.*` исчезают после навигации — переопределять.

# ПОИСК АККАУНТОВ

## 1. topsearch — основной, но с жёстким бюджетом

```js
window.srch=async function(q){
 const r=await fetch('/web/search/topsearch/'+String.fromCharCode(63)
   +'context=blended&query='+encodeURIComponent(q),
   {headers:{'x-ig-app-id':'936619743392459'}});
 if(r.status!==200)return[];
 const j=await r.json();
 return (j.users||[]).slice(0,12).map(u=>u.user.username);
};
```

Пауза 2.5 секунды. **Бюджет около 40 запросов на сессию** (замер 21.09.2026:
после 40-го запроса списки пошли пустыми при HTTP 200). Восстанавливается
примерно через час. ⛔ Пустой список — не «нет аккаунтов», а исчерпанный
бюджет. Продолжать нельзя, надо ждать.

## Простые запросы дают вдвое больше, чем составные

Замер 19.09.2026 по Сесеху. Десять запросов вида `villa seseh`,
`2 bedroom villa seseh` дали 13 аккаунтов, почти все известные. Двенадцать
однословных и бытовых — `seseh`, `seseh beach`, `rumah seseh`, `seseh stay`,
`seseh home`, `seseh living` — дали 23 новых.

Instagram ранжирует по имени аккаунта, а не по смыслу фразы. Виллы без слова
villa в нике (`rumahmatisse`, `sesehstays`, `baliamori`, `le.village.bali`)
находятся только бытовыми запросами. Начинать с коротких.

## ⛔ Сесех через topsearch тоже почти выгреблен (замер 21.09.2026)

24 запроса по Сесеху дали 53 аккаунта, из них живых кандидатов-вилл **два**.
Остальное — кафе, магазины, пиццерии, падел-клуб, ресницы, личные аккаунты

## 2. `discover/chaining` — бесплатная замена, бюджет topsearch не тратит


- Печатать текст присваиванием в DOM вместо инструмента ввода.
- Не проверить инбокс до отправки новых директов.
- Завести карточку по номеру из шапки профиля.
- Объявить слой недоступным, не проверив логин вызовом.
- Продолжать topsearch после пустых списков — ждать час.
- Считать пустой topsearch доказательством, что аккаунтов нет.
- Брать кандидатов из chaining, не проверив район по шапке.
- Тратить время на хештеги — эндпоинт пустой.
- Идти в движки раньше шапок.
- Не посмотреть подписи хайлайтов.
- Начать поиск с составных запросов.
- Отправлять один и тот же текст.
- Продолжать после стоп-сигнала.
- Наращивать объём вместо измерения ответов.
- Читать шапку со страницы, а не из meta.
- Слать через приватный broadcast-эндпоинт — роняет сессию.
- Тратить норму на аккаунт уже заведённой виллы или на объект под оператором.
- Считать ответ в директе контактом владельца, не проверив
  `processed_business_suggestion`.

  честнее написать в отчёте, сколько реально ушло и почему.
