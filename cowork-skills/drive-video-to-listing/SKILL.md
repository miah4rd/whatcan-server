# Видеотуры на сайт unicorn-properties.com

Unicorn Property (аренда вилл на Бали). У карточки на сайте есть раздел видеотура — поле `properties.video_url`. Задача: наполнять его.

Плеер умеет **mp4, YouTube, Instagram**. Прямую ссылку на Google Drive не отрисует — найденный YouTube/IG-ролик ставится ссылкой как есть, без перезаливки.

## Железное правило: только API

Google Drive MCP (`search_files`, `get_file_metadata`, `get_file_permissions`), Supabase MCP (`execute_sql`), `WebSearch` / `web_fetch`. Встроенный браузер — только для проверки карточки глазами и для отправки в Green API.

  - `Own listings` — `1KN--pUx3ssDGdg73uT5S3UvnvdRp6VBE`
  - `Co-Broke` — `15Z1VJbgU5oKHW9_kpzEKjsjuXqxXMeh5`
- **`SALES`** — `12-hrwFd9hfvwwpW40Kc22mq-dYiG5tDM`, 29 папок YUD-001…YUD-033. **ЗАМОРОЖЕНО владельцем 12.09.2026: сейлз не трогаем, работаем только с арендой.** Видео там есть (Villa Bayu Uluwatu 690 МБ, Oasis Villas 620 МБ, Dirga Padonan 451 МБ, Strowberry Berawa 283 МБ, папка `Videos` у Zak Tumbak Bayuh с 29 короткими роликами) — не публиковать, пока владелец не снимет заморозку.

Отдельно: **`AMELIA | Listings`** — `1TIhgYtEc7yiVSvvu0nT0FyIEIIbVKnOD`. Внутри есть подветка **`RENTAL`** — `16Pfw2SFvP2RwQxcSGWOzgTGvAFbwHhHO` (создана 11.09.2026), арендные объекты Амелии лежат там, а не в корне.

## ⛔ Drive-1. Обход рекурсивный, до дна

Раньше прогон ходил на два уровня и пропустил и подветку `RENTAL` у Амелии, и подпапки третьего уровня. **Заходить во ВСЕ вложенные папки, пока они не кончатся.** Папка внутри карточки листинга с названием `Videos`, `VIDS`, `Final Lr`, `PICS`, `Pictures`, `Photos`, `photos`, `<slug>-photos`, `Details`, `Renders` — это не повод её пропустить, видео лежит именно там.

Порядок:
1. Перечислить подпапки: `parentId = '<id>'`, pageSize 100, пагинация до конца.
2. Следующим запросом сразу и видео, и подпапки следующего уровня:
   `(parentId = a or parentId = b ...) and (mimeType contains 'video/' or mimeType = 'application/vnd.google-apps.folder')`
3. Повторять шаг 2 с новыми найденными папками, пока запрос не вернёт пусто.

Экономия: десятки `parentId` через `or` в один запрос. Весь арендный обход укладывается в 6-8 запросов.

## Drive-1b. Контрольный сплошной поиск — обязателен

Дерево можно обойти идеально и всё равно пропустить файл, залитый мимо структуры. В конце обхода:

```
mimeType contains 'video/' and owner = 'me'
```

pageSize 100, пагинация. Вернёт всё видео аккаунта, включая маркетинг и обучалки — из выдачи берутся только те, чей `parentId` лежит в арендных деревьях; незнакомые родители резолвятся через `get_file_metadata`. Именно так нашлась ветка `SALES`, которой в регламенте не было.

Быстрый вариант для ежедневного прогона: `mimeType contains 'video/' and createdTime > '<дата минус 2 дня>'`.

## Drive-2. Сматчить папку с листингом

- Код `R-YUD-070` в названии папки — это и есть `properties.id`.
- **Нумерация Амелии `AME-016` НЕ совпадает с ID на сайте.** Матчим по названию виллы: имя из папки ищем в `property_private.owner_name` и `notes` через ILIKE, сверяем район и спальни. У виллы часто два листинга — продажный (`AME-016`) и арендный (`R-AME-016`); берём арендный. Арендного нет (`AME-026 Melasti N02`) — в отчёт «не сматчено».
- Папки Co-Broke без кода матчатся по владельцу + район + спальни: `Sudirta seseh 1` → `R-YUD-074`, `Sudirta Seseh Joglo` → `R-YUD-075`.
- Не подтвердилось — не трогаем, в отчёт с причиной.

Схема: `properties` — `id, title, area, bedrooms, monthly_price_idr, yearly_price_idr, video_url, is_draft, images`. Колонки `location` и `price_monthly` **не существует** (район — `area`, цена — `monthly_price_idr`). Внутренние данные — `property_private` (`property_id, owner_name, notes`; колонки `address` нет).

## Drive-3. Отсеять уже поставленные

```sql
SELECT id, title, video_url FROM properties WHERE video_url IS NOT NULL AND video_url <> '';
```

Заполнено — пропускаем. Перезапись только по прямому указанию владельца (см. ниже).

## Drive-4. Поставить видео

- SQL-обёртка `public.import_property_video(p_property_id text, p_url text, p_ext text DEFAULT NULL)`.
- Edge-функция `import-property-video` (проект `zveamkyyzfztzppwavws`, Verify JWT выключен) — качает видео, кладёт в `property-videos/<ID>/<ts>-<uuid8>.<ext>` и сама пишет `video_url`. Предыдущий ролик и постер удаляет.

```sql
SELECT import_property_video('R-YUD-070','https://drive.google.com/file/d/<FILE_ID>/view','mov');
```

Третий аргумент — расширение (`mp4`/`mov`/`m4v`/`webm`), Drive отдаёт `application/octet-stream`. По умолчанию mp4.

Успех: `{"status":200,"bytes":32336777,"source":"drive-transcode-720p","video_url":"https://..."}`

### ⛔ Доступ по ссылке — единственное, что я не могу сам

Перед вызовом — `get_file_permissions`, нужен элемент `{"type":"anyone"}` с ролью `reader` или `writer`. Нет его — функция получит от Drive HTML-заглушку и вернёт `422 unexpected content-type "text/html"`. При этом `video_url` **не перезаписывается**, функция падает до записи.

`share_file` из Drive MCP требует конкретный `emailAddress` и галку «Anyone with the link» поставить не умеет; `update_file` меняет только название и родителя. **Это делает человек:** файл → Share → General access → Anyone with the link → Viewer.

Постоянное решение, предложено владельцу 12.09.2026: выставить доступ один раз на родительские папки (`Own listings`, `Co-Broke`, `AMELIA | Listings`) — наследуется на всё новое внутри. Альтернатива вдолгую — сервисный аккаунт Google с ключом, тогда права ставятся через Drive API напрямую.

### Вес ролика: целимся в 20-25 МБ

Решение владельца 08.09.2026. Ролики вертикальные, сняты на телефон и смотрят их с телефона.

- `TARGET = 25 МБ` — цель. Оригинал легче — берём как есть.
- `MAX = 45 МБ` — потолок. Supabase Free не принимает объекты больше **50 МБ** (Settings → Storage → Global file size limit, только апгрейд плана). Бакет настроен на 200 МБ, но выигрывает меньший лимит — плановый.

Алгоритм: размер через `Range: bytes=0-0`; больше 25 МБ и ссылка на Drive — берётся веб-транскод `get_video_info?docid=<ID>&drive_originator_app=303`, поле `fmt_stream_map`, порядок itag **22 (720p) → 18 (360p) → 37 (1080p)**, первый влезающий в 45 МБ. Практика: оригинал 179 МБ → 32 МБ 720p, оригинал 219 МБ → 40 МБ 720p. Транскода нет и оригинал больше 45 МБ — 413, жать руками; ffmpeg в песочнице есть, но сети у песочницы нет.

**Качество исходника важнее нашего сжатия.** Ролик, прошедший через WhatsApp, уже убит отправителем: R-YUD-074 приехал 464×832 при 0.7 Мбит/с.

## ⛔ Из WhatsApp видео не забирается

Проверено 10.09.2026. `getChatHistory` по группе Unicorn Rental отдал 179 сообщений за месяц: 11 `imageMessage` и **ноль** видео, ссылок на скачивание нет. Green API на текущем инстансе видеосообщения в историю не кладёт.

Значит: **ролик, не попавший в папку листинга на Drive, для нас не существует.** Видно в чате, но нет на Drive — это строка отчёта «есть в WhatsApp, не залито на Drive». Правило команде уже озвучено в группе: «AI picks up video materials only from Google Drive».

Отдельно: сообщение «сделал видео на эти листинги» в чате ≠ факт. 11.09.2026 Юди написал, что снял ролики для R-YUD-097 и R-YUD-042, а залил Ischia и Uma Avaya 3BR. **Проверять папки, а не верить сообщению**, и в отчёте называть ID, по которым видео так и нет.

# ИСТОЧНИК 2 — интернет (добор)

Указание владельца 11.09.2026: искать видеотуры в интернете, но совпадение должно быть 100%.

## ⛔ ГЕЙТ 100%

Ролик ставится, только если выполнены **все четыре** условия:

1. **Источник принадлежит вилле** — свой сайт, свой одно-объектный аккаунт IG/YouTube, OTA-страница именно этого юнита. Агентские подборки и блогерские обзоры не считаются.
2. **Вилла одиночная либо юнит назван явно.** Комплекс похожих юнитов (Tofino, Aluna, SWOI, Aquamarine, Sin Sin) — отказ.
3. **Совпали район и число спален.** Разошлись — сначала выясняем, чья ошибка.
4. **Совпали минимум два опознаваемых кадра** с нашей галереей (`properties.images`): фасад, форма и плитка бассейна, лестница, планировка кухни.

Не сошлось — в отчёт «найдено, не прошло гейт: <причина>».

## Что работает, а что нет

Пилот 11.09.2026 по 12 названным виллам, прошло 0. **Обычный веб-поиск по имени виллы даёт каталоги и OTA, а не видеотуры юнита.** Пусто по: Villa Azul, Ischia, Albi, Amor, Aquamarine III, SWOI Loft, Loft@Tabanan, Casa Nalani, Villa Eliza.

- **Villa Sin Sin** (R-YUD-055) — официальный YouTube `Ib9121hpZxM` на villasinsin.com/video. Отказ по п.2: комплекс из трёх одинаковых 2BR, плюс это имиджевый фильм.
- **Villa Maxwell** (R-YUD-051) — maxwellbali.com, одиночная 4BR в Buwit, управляет Rhea Group, совпадает с `owner_name`. Личность подтверждена, но видео на сайте нет; непроверенная точка — IG `@maxwellvillabali`.
- **Tofino Villas** (R-SAI-20) — сайт говорит «комплекс **двух**спальных», у нас 3BR. Отказ по п.3 и повод перепроверить листинг.

Вывод: интернет-добор осмысленен только по одиночным виллам с уникальным именем и своим аккаунтом — это около десятка объектов из 79 живых арендных без видео. Комплексы гейт не пройдут.

Найденное в интернете идёт **на апрув владельцу**, а не сразу на сайт. После апрува: `UPDATE properties SET video_url = '<url>' WHERE id = '<ID>';`

# Перезапись существующего видео

По умолчанию не перезаписываем. Но если владелец сказал ставить — ставим, возражение достаточно высказать один раз.

Прецедент 12.09.2026: ролик `Uma Avaya 3BR.mp4` поставлен на `R-YUD-071`, хотя листинг 2BR, а в ролике 3BR, и там уже стояло своё видео. Возражение озвучено (тур по трёшке на карточке двушки + затирание корректного видео), владелец подтвердил — сделано.

**Перед перезаписью проверить, что старое восстановимо:** оригинал предыдущего ролика должен остаться на Drive (для 071 это `reels16.mp4` в его папке). Есть оригинал — риск нулевой, вопрос лишний. Нет оригинала — сказать об этом до перезаписи, потому что edge-функция удаляет прежний объект из бакета.

# Проверка

```sql
SELECT id, video_url FROM properties WHERE id IN (...);
```

Плюс открыть `https://unicorn-properties.com/property/<ID>`, нажать «Video tour», убедиться что первый кадр отрисовался. Чёрный прямоугольник = битый файл: обнулить `video_url` и перезалить.

Кнопка находится по `find` («Play video tour»); если ref возвращает «outside the viewport» — страница ещё грузится, взять скриншот и кликнуть по координатам.

Занятое место:
```sql
SELECT bucket_id, count(*), pg_size_pretty(sum((metadata->>'size')::bigint))
FROM storage.objects GROUP BY bucket_id;
```

Осиротевшие объекты:
```sql
SELECT o.name, round(((o.metadata->>'size')::bigint)/1048576.0,1) AS mb
FROM storage.objects o
WHERE o.bucket_id='property-videos'
  AND NOT EXISTS (SELECT 1 FROM properties p WHERE p.video_url LIKE '%'||o.name);
```
Удалить SQL-ом нельзя: `storage.protect_delete()` кидает `42501`. Только Storage API или дашборд. Сирот показывать владельцу, а не удалять молча.

# Анонс в WhatsApp Unicorn Rental — по-английски

Указание владельца 10.09.2026. После каждого **добавленного и проверенного** видеотура — сообщение в группу **Unicorn Rental** (`120363411017702009@g.us`) через Green API; реквизиты и способ отправки — в скилле `unicorn-whatsapp-greenapi`.

- **Только английский.**
- Один листинг = одно сообщение, ссылка последней строкой на своей строке (иначе не будет превью).
- Формат:

```
Video tour added - <N>BR <area>, IDR <price>/month.
https://unicorn-properties.com/property/<ID>
```

- Пауза 2-3 секунды между сообщениями.
- Ничего не добавлено — в группу **не пишем**.
- Отправка не прошла — вывести владельцу готовый текст и сказать, что сломалось. Не отчитываться об отправке, которой не было.
- `idMessage` каждого сообщения — в отчёт.

Периодически напоминать команде в группе (по-английски): грузить ролики в папку листинга на Drive, оригиналом с телефона а не пересланным через WhatsApp, и ставить доступ Anyone with the link.

# Отчёт владельцу

```
Drive: обойдено папок N (аренда), видео найдено X, уже на сайте Y
Добавлено: Z — <ID> ..., ссылки на листинги
Отправлено в Unicorn Rental: Z сообщений (idMessage ...)
Интернет: проверено N, прошло гейт Z, на апрув: <ID> — <ссылка> — <чем подтверждено>
Не прошло гейт: <вилла> — <какой пункт не сошёлся>
Есть в WhatsApp, не залито на Drive: <вилла>
Не сматчено: <папка> — <почему>
Нужен доступ по ссылке: <файл + прямая ссылка>
```

Ничего нового — одна строка «новых видео нет».

# Правила

- Обход рекурсивный до дна. Папка внутри листинга не пропускается из-за названия.
- Drive-ссылку в `video_url` не ставить — плеер её не отрисует.
- Не сматчилось — так и написать, а не привязать наугад.
- Ветка `SALES` заморожена, пока владелец не скажет иначе.
- Не отчитываться «нет новых видео», не сделав контрольный сплошной поиск.
- Вкладки браузера, если открывались, закрыть в конце.
- Отчёты короткие, по существу.
