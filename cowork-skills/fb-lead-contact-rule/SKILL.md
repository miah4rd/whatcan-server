# Опознание виллы по фото пина и отбор контакта владельца

Правило источников контакта целиком — в `bali-catalog-sourcing-rule`, раздел 1
(1А телефон с пина, 1Б собственный домен виллы на пине, 1В Instagram).
Здесь — механика цепочки фото и опознания.

---

## ⛔ СЛОЙ 1В: INSTAGRAM ДЛЯ НОВОСТРОЯ СЕСЕХА И ЧЕМАГИ

**Согласовано владельцем 15.09.2026.** Повод: замер того же дня показал, что
в Сесех/Чемаги/Мунггу **68 виллы-пинов из 193 (35%) не имеют ни телефона,
ни сайта**. Это новострой. Единственный путь к владельцу — его Instagram.

```
пин без телефона и без сайта
  -> фото с пина (Places photos)
  -> поиск по картинке
  -> аккаунт виллы в Instagram
  -> WhatsApp в шапке профиля
```

Аккаунт виллы в Instagram считается продолжением пина: это витрина самого
объекта, а не каталог посредника. Признак посредника тот же, что везде —
один аккаунт ведёт несколько разных вилл под своим брендом (`sesehhomes`,
`baliluxvillas` — такие отсеивать).

В карточку: `CONTACT SOURCE: Google Maps pin -> Instagram bio (@аккаунт)`.

**Замер эффективности этого слоя ещё не сделан.** Первый прогон должен быть
на 10 объектах с фиксацией: сколько пинов дали аккаунт, сколько аккаунтов
дали номер, сколько номеров прошли дедуп. Цифры записать сюда.

|---|---|---|
| Чангу, Переренан, Умалас, Берава | ~60% | Карты работают, идти от карт |
| **Сесех, Чемаги** | **5%** (1 новая из 21) | Пиновый слой выгреблен |

**Уточнение 15.09.2026 — «выгреблен» относится только к слою телефонов.**
Полный разрез по Сесех/Чемаги/Мунггу, 193 виллы-пина:

| слой | сколько | доля |
|---|---|---|
| пин + мобильный телефон | 54 | 28% — действительно почти весь в CRM |
| пин без телефона, но со своим доменом | 69 | 36% — слой 1Б |
| пин без телефона и без сайта | 68 | 35% — слой 1В, Instagram |

То есть район не выгреблен, выгреблен один способ добычи из трёх.

### Для Чангу / Переренан / Умалас / Берава — от карт
Places API → фильтры → проверка отзывов → поиск по картинке при необходимости.

### Для Сесеха и Чемаги — слои 1Б и 1В, а не FB-группы
Виллы Сесеха и Чемаги часто вообще не имеют телефона на пине — только
собственный сайт или аккаунт в Instagram. Отсутствие телефона не значит
отсутствие контакта.

FB-группы там не работают как источник: пост несёт спальни и цену, но
**не называет виллу**, а без имени нет ни пина, ни объекта. Тратить на группы
время только когда пост прямо называет виллу.

### Непрочёсанные пласты (в порядке приоритета)
1. **Instagram по гео и хэштегам Чемаги/Сесеха** — слой 1В, согласован.
2. Периметр вокруг Сесеха: Тумбак Баю, Будук, Няньи, Кедунгу — спрос
   перетекает туда первым, а собирали мы их мало.

### Недельная сверка новых пинов
База по району выгребается один раз, дальше ценность в приросте — новострой
в Сесехе и Чемаги появляется постоянно. Раз в неделю прогонять сетку
`places:searchNearby` по тем же точкам и сравнивать с amoCRM по номеру.
**Это единственное оставшееся назначение сетки** — как источник прогона она
мертва (замер 15.09.2026, см. `bali-catalog-sourcing-rule` ШАГ 3).

## ЗАЧЕМ НУЖЕН ФИЛЬТР ПО ФОТО

Google Maps даёт имя, район и телефон, но **никогда не даёт цену и почти никогда
не даёт число спален**. Без них карточка не проходит наш таргет.

Решение: взять фото с пина и прогнать его **поиском по картинке**. Если вилла
всплывает в каталоге, на OTA или в FB-группе — оттуда видно спальни, цену и то,
что она публикуется прямо сейчас. Плюс так же находится аккаунт виллы
в Instagram для слоя 1В.

Проверено 31.08.2026: Villa Tilu (Переренан) опознана как
«VILLA TILU, CANGGU, **3 bedrooms**, from USD 160 per night» — ушла из линии 2BR
без звонка.

## РАБОЧАЯ ЦЕПОЧКА (встроенный браузер)

### 1. Фото с пина через Places API

Ключ Places — в навыке `api-first-rule`. Маска `places.photos`,
у каждого фото есть `widthPx` / `heightPx`.

```js
const gp=async n=>{
 const r=await fetch('https://places.googleapis.com/v1/places:searchText',{
  method:'POST',headers:{'Content-Type':'application/json','X-Goog-Api-Key':K,
  'X-Goog-FieldMask':'places.photos'},
  body:JSON.stringify({textQuery:n,maxResultCount:1})});
 const p=(await r.json()).places[0];
 const w=p.photos.filter(x=>x.widthPx/x.heightPx>1.25).sort((a,b)=>b.widthPx-a.widthPx);
 const pick=w[0]||p.photos[0];
 const m=await fetch('https://places.googleapis.com/v1/'+pick.name+'/media'
  +String.fromCharCode(63)+'key='+K+'&maxWidthPx=1200&skipHttpRedirect=true');
 return (await m.json()).photoUri;
};
```

### 2. Заливка в поиск по картинке

**Страница:** `https://www.google.com/imghp?hl=en`.
Не `lens.google.com/upload` (кнопка Search программно не жмётся),
не `lens.google.com/v3/upload` (CORS, `Failed to fetch`),
не `uploadbyurl` (подписанный URL Places отвергается: «No image at the URL»).

```js
const cam=[...document.querySelectorAll('div[role=button],span,div')]
 .filter(e=>/search by image/i.test(e.getAttribute('aria-label')||''))[0];
cam.click(); await new Promise(r=>setTimeout(r,1500));
const b=await (await fetch(photoUri)).blob();
const dt=new DataTransfer();
dt.items.add(new File([b],'v.jpg',{type:'image/jpeg'}));
const inp=document.querySelector('input[type=file]');
inp.files=dt.files;
inp.dispatchEvent(new Event('change',{bubbles:true}));
```

Страница уходит на выдачу, вызов падает с «Inspected target navigated or closed» —
**это нормально**. Результат читать следующим вызовом `get_page_text`
(900-1500 символов, нужен блок «Visual matches»).
Одна вилла = 3 вызова: `navigate` → JS с заливкой → `get_page_text`.

### 3. ГЛАВНАЯ ЛОВУШКА: какое фото брать

Соотношение сторон — плохой прокси для «экстерьер». На живых примерах:

- **Maniya Villas** — самое широкое фото оказалось спальней. Выдача: матрасы,
  простыни, гостевые дома на Яве. Мусор.
- **LA MAISON Echo Beach** — самое широкое оказалось воротами. Выдача:
  автоматические ворота и заборы. Мусор.
- **Villa Tilu** — попался общий план. Вилла опознана сразу.

Годится только широкий общий план: фасад, бассейн, вилла целиком.
Мусор определяется автоматически: в тексте выдачи нет ни одного из слов
`villa | bali | bedroom | kamar | disewakan`. Тогда брать следующее фото.
**Больше трёх попыток на виллу не делать** — писать `IMAGE: NO MATCH` и идти дальше.

## ТРАКТОВКА РЕЗУЛЬТАТА

| Что нашлось | Что даёт | Метка в карточку |
|---|---|---|
| Каталог долгосрочной аренды (BHI, rumah123, Bali Villa Hub) | Спальни + цена + публикуется сейчас | `LISTED LONG TERM` |
| OTA (Agoda, Booking, Airbnb, Traveloka) | Спальни + посуточная цена | `OTA ONLY` — приоритет 3 |
| Пост в FB-группе | Публикуется сейчас, часто цена и срок | `FB LISTED` + дата поста |
| Свой сайт виллы | Спальни, иногда цена, **и контакт по слою 1Б** | `OWN SITE` |
| Аккаунт виллы в Instagram | **Контакт по слою 1В** | `OWN IG` |
| Ничего после 3 фото | — | `IMAGE: NO MATCH` |

Совпадение — положительный сигнал. Его отсутствие ничего не доказывает:
маленькие виллы часто нигде не опубликованы, и это как раз наш клиент.
**Не отсеивать по `NO MATCH`.**

Отдельно: каталог чаще даёт **посуточную** цену, а не месячную. Месячная всплывает
только если вилла висит в каталоге долгосрочной аренды или в FB-группе.

## ОТБОР КОНТАКТА ВЛАДЕЛЬЦА

- Номер только мобильный `+628`. Стационарные `+62361` не заводить — WhatsApp
  на них нет. **Замер 15.09: на сайтах вилл Сесеха стационарный рядом
  с мобильным встречается часто** (Villa Matahari, Villa The Shore) — брать
  мобильный, стационарный отбрасывать.
- Домен из `websiteUri` не агентский. Отсеянные по факту: `houseofreservations`,
  `elevate-villas`, `breigvillas`, `casalivingbali`, `anambalihospitality`,
  `optimumbali`, `coleva.asia`, `cpmbali`, `alexvillasgroup`, `lyvin.co`,
  `balimanagement.villas`, `villabalimanagement.com`, `navyagroup.id`,
  `stayatsolo`, `betterplace.cc`, `terragroupbali`, `mahavilas`, `baliinvestclub`,
  `mjnorth-estate`, `house-renting.com`, `elitehavens.com`,
  `book.spaciousbali.com`, `booktropically.com`, `book.orivista.com`,
  `book.balinestvillas.com`, `voyabay.com`, `islandboyhomes.com`,
  `unicornvillasbali.com`. Собственный сайт виллы
  (`saltvillacanggu.com`, `balimeritavilla.com`, `puricangguvillas.com`,
  `villamatahari.com`, `villablackbird.com`, `maisonmatissebali.com`) — НЕ
  агентство, брать.
- ⛔ **Осторожно с регуляркой по домену.** Шаблон `villas\.com` вырезает
  собственные домены `theleovillas.com`, `lumahi-villas.com`,
  `sejukbeachvillas.com`, `shalimarvillas.com`. Ошибка поймана 15.09.2026 —
  отсекла 4 законных кандидата из 16. Проверять регулярку на списке известных
  собственных доменов перед прогоном.
- Приставка «by <компания>» в названии = управляющая компания
  (Villa Bangkuang by Nakula, Canggu Villa Go by Nagisa, The Hollow by Bali Prime).
- Совпадение номера у двух вилл = оператор, а не владелец. Известные:
  `0361738999` (Villa Arita, Bumbak Park — Nakula);
  `0361737498` (Villa Semarapura, Seseh Beach Villas);
  `+6285219526780` (Kristina Villa, Villa Nadine);
  `+62881081966339` (Umalas Living, Seseh Living, Berawa Village, Cemagi Townhouse);
  `+6281235137889` (Villa Cabana Kedungu, Canggu Circle, Villa Pomelo);
  `+6282147909060` (Casa Umari Canggu, Villa Taman Kedungu);
  `+6281238403498` (Villa Lima Hati, Villa Arev).
- Номер-заглушка `0899-9999997` не брать.
- **Kibarer / villabalisale.com исключены полностью.**
- Не брать номер из текста поста, кроме прямого заявления владельца
  («I am the owner», «I'm the owner and managing it»). Перед проверкой отзывов
  и постов нормализовать апострофы: `.replace(/[‘’]/g,"'")`.

## НОВЫЕ РАЙОНЫ БЕЗ ОТЗЫВОВ

У новостроя нет ни отзывов, ни листингов. Проверять по фото пина, достроена ли
вилла: готовый объект — заводим, 3D-рендер — отклоняем.
Так прошли Villa Mecaru, Villa Ra, Villa Cempaka, VILLA BAGAS, Exsotis, Capila;
отклонён SESA VILLAS (рендер).

## ЧТО ПИСАТЬ В КАРТОЧКУ

Весь текст внутри amoCRM — **только на английском**. В примечании:

```
SOURCE: ...
CONTACT SOURCE: Google Maps pin | Google Maps pin -> own villa domain (<домен>) |
                Google Maps pin -> Instagram bio (@аккаунт)
VERIFIED: ... (спальни / срок / цена / где опубликована — с цитатой источника)
IMAGE: LISTED LONG TERM | OTA ONLY | FB LISTED | OWN SITE | OWN IG | NO MATCH
TO ASK ON FIRST TOUCH: ... (всё, что не подтверждено)
```

Если контакт взят по слою 1Б или 1В — **в TO ASK ON FIRST TOUCH обязательно
вопрос «владелец или управляющий»**: номер с сайта и из шапки профиля это
сильный сигнал, но не то же самое, что номер с пина.

Тег `SRC:AI` — по нему считается вся аналитика. `created_by` равен 0 у всех
карточек, по нему считать нельзя. Карточки брокера (`R-YUD-050`, `YUDR-011`,
входящие `Lead #NNN`) в метрику не мешать.
