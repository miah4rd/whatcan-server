# ⛔ АНОНС ЛИСТИНГА: ОДИН ЛИСТИНГ = ОДНО СООБЩЕНИЕ, ТЕКСТА МИНИМУМ

Указание владельца 08.09.2026, после того как два листинга ушли одним длинным
сообщением на 20 строк.

## Три жёстких правила

1. **Одна ссылка в сообщении.** Два листинга — два отдельных сообщения.
   WhatsApp рисует превью только для **первой** ссылки; вторая остаётся голым
   текстом. Превью карточки — это и есть то, ради чего брокер откроет ссылку.
2. **Ссылка последней строкой, на своей строке.** Не в середине абзаца.
3. **Обложка проверена глазами ДО отправки.** Превью в WhatsApp — это
   `og:image`, то есть `images[1]`. Критерий — в `listing-photo-standard`,
   коротко: **на кадре должно быть видно здание виллы**, бассейн у глухой стены
   не годится. Переотправка стоит удаления сообщений в группе из ста человек.

## ⛔ WHATSAPP КЭШИРУЕТ ПРЕВЬЮ ПО URL

Проверено 08.09.2026. Поменяли обложку на сайте, удалили сообщение, отправили
заново **тот же** URL — в превью осталась старая картинка. Кэш привязан к URL,
повторная отправка его не сбрасывает.

Обход — версионный параметр, URL становится новым и WhatsApp перечитывает
страницу заново:

```
https://unicorn-properties.com/property/R-YUD-090?v=2
```

Сайт параметр игнорирует, страница открывается нормально. Номер увеличивать при
каждой следующей замене обложки того же листинга.

## Формат — держаться этого объёма

```
New listing - <N>BR <area>, IDR <price>/month, available <now / from 18 Sep>.
Pre - temporary photos, sizes to follow.
<listing url>
```

Три строки. Всё, что не влияет на решение брокера показать объект клиенту,
из анонса выкидывается.

**Что НЕ пишем в анонсе:** объяснение, что такое Pre, кто и когда поедет
доснимать, источник фото, сколько кадров, чего не хватает в данных, номера
лидов, имена и телефоны владельцев. Это живёт в `property_private.notes` и в
примечании amoCRM.

Фото от владельца, а не из интернета — вторую строку заменить на
`Photos supplied by the owner.` Нечего сказать по фото — строку убрать совсем.

**Одна короткая строка предупреждения** добавляется, только если без неё брокер
назовёт клиенту неверную цену или не тот объект. Пример:
`Small complex of identical units, check with us before quoting.`

## Сводный репорт прогона в группу НЕ отправляется

## Пауза между сообщениями

2-3 секунды между отправками, иначе превью у части сообщений не успевает
подтянуться.

## Как отправлять

`fetch()` из встроенного браузера со вкладки на нейтральном домене
(`example.com` или `unicorn-properties.com`). Green API отдаёт CORS.

```js
const B='https://7105.api.greenapi.com/waInstance710522728159';
const T='8a3d673d65744bcd847708c8c871896f69e3a09c82784900a5';
const r=await fetch(B+'/sendMessage/'+T,{
  method:'POST',
  headers:{'Content-Type':'application/json'},
  body:JSON.stringify({chatId:'120363411017702009@g.us', message:'text', linkPreview:true})
});
await r.json();   // {"idMessage":"BAE5..."} = ушло
```

Проверка живости: `GET /getStateInstance/<token>` → `{"stateInstance":"authorized"}`.
Иначе — новый скан QR в `https://console.green-api.com/instanceList/710522728159`.

Отправка файла — `/sendFileByUrl/` с полями `chatId`, `urlFile`, `fileName`, `caption`.

## Исправить уже отправленное

```js
await fetch(B+'/deleteMessage/'+T,{method:'POST',
  headers:{'Content-Type':'application/json'},
  body:JSON.stringify({chatId:C, idMessage:'3EB0...'})});
```

Работает только на свои сообщения и в окне, которое даёт WhatsApp. Ответ `200`
с пустым телом = удалено. **Все `idMessage` записывать в журнал прогона** —
без них не откатить.

## Правила

- **Отправка от лица владельца — действие с последствиями.** В группу из ста
  человек шлём только согласованное. Автозадача шлёт анонс только после явного
  апрува публикации.
- Отправка не прошла — вывести владельцу готовый текст и сказать, что сломалось.
  **Не отчитываться об отправке, которой не было.**
